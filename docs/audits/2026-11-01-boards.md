## Correction

The C3 profile inherited `board_build.f_cpu = 240000000L` from the shared
environment. ESP32-C3 supports a maximum CPU frequency of 160 MHz; its board
definition and bundled SDK default both specify 160 MHz. Arduino's startup
passes `F_CPU / 1000000` to `setCpuFrequencyMhz()` and ignores the return value,
so compilation alone did not flag this unsupported request.

The C3 profile now explicitly specifies `160000000L`. A compile-time check in
`main.cpp` rejects C3 requests above 160 MHz, so a future change of the shared
default cannot silently reintroduce the mismatch. Other profiles retain their
240 MHz CPU configuration. No ASIC frequencies or voltage settings change.

This establishes a configuration fault, not a measurement that the C3 ever
ran at 240 MHz. No physical hashrate gain or electrical cause is inferred.
