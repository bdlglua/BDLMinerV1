# Firmware audit — 2026-10-27

These corrections are included in release v1.5.2. The earlier v1.5.1 binaries are unchanged.

## Corrections

- **Stratum V1 responses:** require a boolean authorization result, reject empty job identifiers, and ignore duplicate successful authorization replies so they cannot republish work. Malformed responses retain an actionable error.
- **Active share difficulty:** update the displayed V1 difficulty when work becomes active. A `mining.set_difficulty` announcement for the next job no longer changes the difficulty shown for the job still being mined.
- **Stratum V2 session changes:** process `SetExtranoncePrefix` and `SetGroupChannel` without reconnecting. Snapshot the prefix when each job arrives, including future jobs activated later; ignore group-addressed prefix changes. Validate channel closures and ignore closures for unrelated channels. Parse truncated messages without applying partial state changes.
- **Updates and restarts:** reserve the shared OTA owner before watchdog restarts and physical factory resets. Defer web-triggered restarts while GitHub OTA owns the updater. A completed web upload can still reboot with its retained ownership. New updates cannot begin while a restart holds the reservation.
- **Timer wrap:** avoid the zero sentinel when scheduling a web restart across the approximately 49.7-day `millis()` wrap.
- **Persistent settings:** bound the payload again immediately before record-size arithmetic and copying. Preserve the existing CRC/dual-slot format. Exercise the exact 8,192-byte limit, oversized rejection and recovery of the previous record; compile the storage test with FORTIFY and string-overflow warnings treated as errors.
- **Pool URL entry:** a complete `stratum2+tcp://host:port/authority` URL fills the host, port, V2 selector and key when the field loses focus. Main and backup controls remain independent. Reject malformed URLs without partially replacing the other fields.
- **Filtered form validation:** reveal invalid settings before reporting browser validation errors. A hidden required field no longer leaves Save blocked without a visible field to correct. Numeric, power and temperature validation remains enabled.
- **Pool API statistics:** accept difficulty/share/hashrate values serialized as either JSON numbers or numeric strings. Missing, negative, non-finite or malformed difficulty/share values retain their previous valid records. Match Public Pool domains at a DNS-label boundary and normalize host case.

## Review and validation

The review covered the mining/work/queue pipeline, V1 and V2 sessions, Noise integration, network input bounds, settings migration and persistence, local HTTP/backup/upload handlers, signed GitHub updates, thermal supervision, restart coordination, physical rendering, web/history/diagnostics, pool APIs, optional MQTT/notification services and release tooling. Pinned cryptographic libraries remain unchanged.

Regression cases reproduced the authorization, active-difficulty, restart/OTA, timer-wrap, V2 prefix/group, numeric pool-statistics and web-form failures before the corresponding fixes.

Validation includes:

- Portable SHA-256d vectors and 14,336 filter comparisons; queue generations, 32/64-bit records, counter wrap, persistence failures, thermal limits and stalled-supervision shutdown.
- An independent Noise peer with certificate/AEAD/replay checks; protocol parsing under AddressSanitizer/UndefinedBehaviorSanitizer; fragmented local sockets and partial writes. Python reconstructs four submitted proofs across old/new prefix snapshots and a group reassignment.
- Production HTTP upload, settings persistence, updater scheduling, restart ownership and pool-statistics fault tests.
- **51 browser regressions**, including complete V2 URLs and hidden invalid settings, plus six release/asset-tool tests.
- Physical renderer checks for eight pages in English/French across seven panel sizes, with buffered/direct parity and update recovery.
- Local ESP32 headless and LilyGO T-Display builds, plus the repository's ten-variant build/USB-packaging CI matrix.

The optimized SHA kernels, assembly loops, thermal thresholds, expiring mining-safety lease, saved user limits and partition layouts are unchanged. The default user agent remains `BDLMinerV1/<version>`; this audit does not restore a NerdMiner identity by default.

## Physical validation still needed

No physical miner is connected to this workspace. Real USB/battery temperatures, sustained hashrate, sensor readings, hardware flash/reboot behavior and live Public Pool V2 operation require tests on the actual boards. Host benchmark figures are CPU measurements on the test machine. This audit does not establish that the entire program is free of all defects.
