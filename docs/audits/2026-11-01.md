# Repository review — 1 November 2026

Starting point: `59f912dc75eb29685162f01c89bcc1241213a1ee` (v1.9.11).
The changes below are on `main`, pending a firmware release.

## Scope

Reviewed the first-party firmware and its interfaces: SHA-256d/work generation,
Stratum V1/V2 and Noise, share submission and counters, saved statistics/history,
settings and WiFi provisioning, thermal supervision, Gamma 601/BM1370 and
NerdNOS/BM1397 backends, board/display code, HTTP/SSE, GitHub updates/firmware
trials, crash reports, market/pool APIs, notifications, MQTT and anonymous reports.
Also reviewed the local web pages, public installer/chat, Python generators,
packaging/statistics scripts and CI/release/site workflows. The Discord setup
script was checked in its local planning mode; no server changes or messages
were made. Vendored cryptography and generated font/assembly data were exercised
through their existing tests rather than rewritten.

## Corrections

| Fault | Result after the change | Regression coverage |
|---|---|---|
| Accepted work used the pool's difficulty at acknowledgment time, even after a vardiff/job change. | V1 submissions retain their work's assigned difficulty. V2 submissions retain the applicable job target, including dynamic targets. Each accepted reply credits that saved value. The candidate's actual difficulty is still shown as its record. | V1 delayed answers after difficulty changes; V2 mixed-target batched acknowledgments; production miner counters. |
| The recent-share log assumed that answers arrive in submission order. | Reply IDs select the matching row. An answer for a row already evicted from the 20-entry display still counts, without modifying a newer pending row. Disconnects leave pending rows unanswered. | Out-of-order rejection/acceptance, log rollover and disconnect. |
| A hidden dashboard kept its SSE connection and received statistics every two seconds. | The stream closes on hide/page departure, then reopens once on visibility/page restoration. Polling remains the fallback. | Real browser/server connection counts, no hidden snapshots, duplicate visibility events, page restoration. |
| An older snapshot of the same boot could rewind live measurements and reset the history session. | Snapshots with an unchanged boot ID and an older uptime are ignored. | Browser regression preserving the current uptime, session and history revision. |
| MQTT's permissive integer conversion accepted partial numbers such as `50oops`, `1.5` and `-oops`. | Power and brightness require a complete integer percentage in 0–100. Embedded NULs, trailing text and oversized numbers are refused. | Production parser: every valid percentage, malformed strings and integer overflow. |
| ASIC settings described the ESP32's thermal steps, despite ASIC firmware using a two-minute pause. | The firmware reports whether it uses steps. The settings page explains the actual pause/cooldown in English and French. | ESP32 thresholds, ASIC pause, disabled limit and French translation. |

## Hashrate and hardware limits

The SHA kernels, assembly timing, CPU/ASIC frequencies, thermal thresholds and
supervision lease are unchanged. A deterministic test executes the production
accounting code over 7,200 irregular intervals, crossing 32-bit engine-counter
wraps. A constant 1 MH/s remains 1 MH/s, a subsequent measured 1.2 MH/s remains
1.2 MH/s, and stopped counters decay to zero. This checks arithmetic; it does
not measure a physical board.

The previously supplied M5 log showed roughly 1.001–1.005 MH/s and did not
capture the reported 1.2 MH/s interval. This review does not establish a physical
cause for that fluctuation or a measured hashrate improvement. Hardware temperature,
power consumption, ASIC stability and real-pool throughput still require board
measurements.
