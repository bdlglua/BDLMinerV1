# Repository and script review — 2026-10-27

Reviewed from commit 6824c3a (v1.5.2). These changes are prepared after that
release; its published binaries and tag are unchanged.

## Coverage

- All project Python tools: PlatformIO environment setup, gzip web assets,
  firmware merging/signing/manifests, installer generation, usage reporting,
  display artwork/fonts/previews and generated SHA assembly.
- Browser scripts and HTML for the dashboard, graphs, measurements, settings,
  backup/restore, uploads and log; the web flasher and both GitHub workflows.
- Firmware modules: mining kernels/work/queues, V1/V2 and Noise, network retries,

This is a code review and regression pass, not proof that every possible defect
has been eliminated.

## Confirmed corrections

1. **Pool hashrate parsing:** reject negative/non-finite rates, overflow and trailing
   garbage. Preserve the last valid ckpool rate when a field is missing or invalid.
   Keep genuine zero rates; accept case-insensitive SI suffixes and whitespace.
2. **Release generation:** stage all selected boards, signatures and manifests
   before replacing output. A later-board/signing failure keeps the previous
   complete output, including its matching signatures. Partial successful builds
   still retain the other boards.
3. **Signing:** verify a temporary signature before publishing it. A wrong signing
   key cannot replace a verified signature. An explicitly configured missing key
   fails instead of silently building unsigned. Tests use temporary test keys.
4. **CLI arguments:** validate version syntax and board names before changing the
   configured version; missing arguments now produce usage errors.
5. **Installer generation:** stage the full site, fail on missing declared factory
   images/unsupported chips/empty board lists, and remove obsolete files on success.
   Refuse output paths that would replace the source release or a parent directory.
6. **Web asset generation:** atomically replace the generated header so failed or
   overlapping writes cannot expose half a C++ header to the compiler.
7. **Usage report:** do not calculate activity from a new asset's entire historical
   count or produce a negative active-miner estimate after a counter decreases.
   Recover from malformed cache files; atomically save the new baseline.
8. **Release workflow:** require the browser regressions to pass before firmware
   publication, including tags pushed independently of main-branch CI.
9. **File handling:** close packaging/HTTP files explicitly and use UTF-8 for HTML
   and generated web headers.

The shared output helper restores the previous directory if publication raises an
exception. This is filesystem staging; it is not a power-loss transaction or a lock
for concurrent release generators targeting the same output.

## Validation

- Native firmware regression suite, including SHA-256d reference/filter vectors,
  V1/V2 protocol and independent encrypted peer, persistence/OTA faults, queue
  generations, history and thermal supervision.
- 51 browser regressions.
- 15 packaging, signing, output rollback, cache and web-asset tests.
- Actual ESP32 headless and LilyGO T-Display builds and USB-image packaging.
- Actual physical display renderer checks across seven panel sizes, eight pages
  and English/French; artwork/font regeneration matches the tracked data, and
  generated fill assembly matches its source generator.
- Python compilation and JavaScript/shell syntax checks.

The nonce loops, SHA assembly, thermal thresholds, safety lease and partitions
are unchanged. No physical miner is attached: sustained hashrate, USB/battery
temperature, hardware flashing and live pool operation still need real-board tests.
