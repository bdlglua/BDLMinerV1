# Follow-up review — 1 November 2026

Starting point: `370922a767bc92ee5b1a8962cf289d175f3ed5c3` (v1.9.12).

Reviewed settings/provisioning, notification delivery, saved statistics,
firmware trials, V1/V2 connection supervision and asynchronous dashboard
requests. The reproducible faults found in this pass are corrected below.

| Fault | Correction | Regression coverage |
|---|---|---|
| A pool could authorize/open a channel without delivering work. Authorization disabled the handshake timeout and reset the failover counter, leaving mining idle and preventing the backup from being selected. | V1 and V2 require initial usable work within the 30-second setup deadline. A session without work counts as a failed attempt, so three such main-pool attempts select the configured backup. Existing work does not need to refresh every 30 seconds. | Real V1 session and reconnect loop, V1/V2 backup selection, timer wrap, valid long-running work, and an independent encrypted V2 peer opening a channel without sending a job. |
| A pending dashboard poll could deliver an old boot's snapshot after a live event from a new boot. The different boot ID was interpreted as another restart, restoring obsolete readings and resetting history again. | An accepted live snapshot supersedes any poll already in flight, including its success response. | Browser regression completing an old poll after a new boot's live snapshot; the new boot, uptime and history session remain current. |
| Failure of that older poll could mark the dashboard offline even after newer live data had arrived. | Errors belonging to a superseded poll are ignored too. | Browser regression returning HTTP 503 after a newer accepted live snapshot; the dashboard stays online. |
| A reboot during measurement preparation could go undetected if the delayed diagnostics still described the original boot and the new boot had higher counters. | Preparation retains the dashboard session and rejects a changed session or firmware before starting the measurement. | Browser regression delivering old diagnostics after a new boot with higher uptime and hash totals; no measurement starts. |

The new V1 timeout and all three dashboard regressions failed before their
corrections. Tests use local deterministic peers and mocked browser APIs;
no hardware or public mining pool is contacted.
