# Gamma fan control and NerdNOS reliability — 1 November 2026

Starting point: `eac0da7f4a689f5da8b10f801bd4590b2b661cf7`.

## Gamma 601

Add Gamma-only saved settings `fanauto` (boolean, default false) and `fanpct`
(integer 30–100, default 100). Both apply live; other boards' schemas do not
expose them. Older records preserve full cooling. Backups round-trip both values.

The web handler sends one atomic configuration containing mode, percentage and
the user thermal limit. Only the ASIC worker accesses the EMC2101. Its direct
setting register 0x4c uses the existing 0..63 PWM encoding, with a write/read-back
on each changed command. The dashboard reports the resulting PWM percentage,
measured RPM, mode and any safety override, instead of a constant 100%.
An unverified command is reported as null rather than as a successful full-speed request.

The independent policy keeps full ventilation during startup or a pause and
when either temperature is unavailable. At default settings, 60 °C ASIC or
80 °C regulator forces full cooling until both have cooled by 5 °C; that
hysteresis survives ordinary mining pauses. Lower user limits advance ASIC
cooling to five degrees below the limit. A disabled user limit retains the
60/80 °C fan override and the existing hard shutdowns.

The automatic curve rises from 30 to 100% over the 20 °C below those thresholds.
Cooling increases immediately; automatic decreases are spaced by at least five
seconds. The raw ASIC diode drives the fan override, including an anomaly still
being qualified by the existing three-reading shutdown filter. Fan I2C errors
assert reset before attempting regulator shutdown and a full-fan request;
faults remain latched.

The user interface offers a keyboard-accessible slider and manual/automatic
selection in Settings > Safety > Cooling. Changes save without an ASIC restart.
Controls and explanations are translated in English/French. The dashboard links
to settings and distinguishes PWM command from measured RPM. A disabled user
temperature limit is no longer described as disabling all Gamma protection.

## NerdNOS

Two reproduced faults are corrected:

- A first verified proof updated the live counter, but the published status
  remained at zero until 50 responses accumulated. Publish each result update.
- Startup checked power/supervision but ignored pool-job invalidation during
  its waits. Check work readiness too and cut power promptly on job loss.

Both new backend assertions failed before the corresponding fixes. Neither
correction changes the BM1397 PLL, NTC conversion or hash/share accounting.

## Validation

- Portable fan-policy tests: all manual percentages/PWM bounds, both thermal
  inputs, missing sensors, hysteresis, adaptive user limits, automatic pacing
  and millis wrap.
- Production Gamma backend with simulated I2C/UART: full fan throughout startup,
  live changes without a reset, no redundant writes, manual/automatic control,
  raw sensor anomalies, pause/resume hysteresis, failed writes and incorrect
  read-back. Existing regulator/diode/fan/supervision/PLL tests remain active.
- Production settings HTTP tests for classic ESP32 and Gamma: persisted live
  fan updates reach the runtime control; failed saves apply nothing.
- Settings validation, migration and backup round trips.
- Full native suite, 93 browser regressions and 16 release/web-generation tests.
- M5StickC Plus2, NerdNOS and Gamma PlatformIO builds, plus the repository's
  twelve-profile CI matrix.

No physical board is accessed. Actual fan starting behavior, RPM and thermal
response have not been measured. This is an unreleased source change; no
release tag is created here. CPU/ASIC frequency profiles, regulator setpoints,
SHA kernels and hard thermal/fan/supply shutdown thresholds are unchanged.
