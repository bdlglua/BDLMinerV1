# BDLMiner 2.0.0-beta.4 — hardware validation preview

- S2/S3/C3 SHA transfers skip an intermediate RAM digest and unroll fixed-size
  copies. Boot checks complete reference digests and enables the new kernel only
  if its local comparison is more than 1% faster. Buffered/full-write fallbacks
  remain. Physical throughput is unmeasured; 1 MH/s is not promised.
- Preserve beta.3's full-width local dashboard and SVG settings icons. The owner
  confirmed those fixes on both M5 and Gamma running confirmed beta.3.
- Provide an EN/FR four-check protocol: M5 rollback before normal confirmation,
  Gamma stability/OTA, deliberate network interruption/recovery and future board
  measurements. The read-only network observer requires operator attribution,
  the same boot, healthy reconnected mining and advancing real counters.
- OTA observation checks old/trial/result boot identities. Cached readings and
  a new restart after the observed trial cannot count as confirmation/rollback.
  An explicit `--reset-command` can request one hardware reset at the trial cue;
  a Linux USB-UART DTR/RTS helper needs only Python's standard library and never
  sends serial data, firmware or an erase command. Its actual wiring/reset still
  requires validation on the owner's identified M5 port.

The owner currently has no ordinary S2/S3/C3 or NerdNOS for physical validation.
M5/Gamma beta.4 OTA, rollback, network recovery and sustained performance remain
pending. Tests/simulation are not counted as physical results.

Unsigned CI images are for manual local-dashboard installation. No release/tag,
automatic update, channel-pointer publication or settings migration is triggered.
Classic ESP32 assembly, ASIC workers, clocks, voltage and thermal/fan controls
remain unchanged. The published stable release remains 1.9.15.
