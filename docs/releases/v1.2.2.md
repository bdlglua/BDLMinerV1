## SHA-256d optimization

- On ESP32-S2/S3/C3, initialize the six zero padding words shared by both SHA blocks once per batch. This reduces text-register writes from 32 to 20 per nonce, plus six writes per batch, and halves the temporary digest buffer from 64 to 32 bytes.
- Select the loop outside the nonce loop. If the optimized hardware path fails its boot known-answer test, retry with complete block writes before deciding whether hardware hashing is usable.
- In the portable C scanner, reuse the already prepared nonce-independent part of round 3. Reject non-candidates using only the necessary end-state updates, and expand the last three message words only when completing a candidate. Keep the unrestricted full-digest path.

The classic ESP32's cycle-timed assembly loops, SHA-256d results, nonce coverage, mining power and thermal protection are unchanged. The register-write reduction is not a measured hashrate gain; sustained hashrate and temperature still require testing on physical boards.

Validation includes 2,048 varied header/nonce combinations and 14,336 exact filter checks against the reference double hash, Bitcoin genesis and existing mining regressions. A register-level model executes the production resumable loop and checks full digests, nonce wrap, stale padding after another SHA user, write counts, hardware ownership and the boot fallback.
