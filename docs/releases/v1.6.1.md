## Gamma 601 frequency profiles and startup fixes

This release adds an **experimental 600 MHz profile** for the Bitaxe Gamma revision 601, with selectable stock and intermediate profiles, automatic fallback, and fixes to regulator setup and startup supervision. **No physical Gamma 601 was available for validation.** Actual hashrate, temperature, stability and accepted pool shares remain to be measured on hardware.

- Choose **525 / 550 / 575 / 600 MHz** under local **Settings > Safety**. The default is **600 MHz**, including older Gamma settings without a saved profile. Changes apply after restart and are included in settings backups. Invalid saved values fall back to 525 MHz; invalid API requests are rejected.
- Keep core voltage fixed at **1150 mV** and the fan at **100%**. Mining-power and thermal limits can reduce the actual clock below the requested profile. This release does not raise voltage.
- Fall back to **525 MHz until reboot** when running above stock and the ASIC reports at least 2% hardware errors in three consecutive ten-second windows, stops responding/progressing, or loses hardware-error telemetry. The fallback survives pool reconnects and ordinary pauses. A failure at stock stops mining.
- Preserve latched shutdowns for excessive temperature, fan/sensor failure, invalid supply/core voltage, excessive current and regulator faults. A failed I2C power-off prevents automatic restart. The independent safety lease remains active during startup and mining.
- Show requested and actual frequency, hardware-error percentage, fallback status and its reason in the local dashboard. Show the fallback on the compact OLED. Hashrate still comes from the ASIC hardware counter, not from the configured clock.

## Regulator and startup corrections

- Correct TPS546 VOUT warning/fault/margin registers to use ratios of `VOUT_COMMAND`, as specified by the ESP-Miner reference. Voltage command/minimum/maximum remain absolute values. All regulator configuration remains volatile; no NVM/STORE commands are sent.
- Allow core power to stabilize before initializing the ASIC and ramp the PLL in **6.25 MHz steps spaced by 100 ms**. Sample fan, power and temperatures throughout startup; require the ASIC diode after its mux/conversion settles.
- Respect changed power limits, obsolete work and expired supervision during the ramp. Use single-chip reads for the ASIC counters and monitor both total hashes and hardware errors.

## Installation and compatibility

For a Gamma 601, use a regulated **5 V barrel supply**, a correctly mounted heatsink and a working fan. At least 4 A is required; **5 V / 6 A (30 W)** is recommended for headroom at 600 MHz. USB alone cannot power ASIC mining. This image is only for Gamma revision **601**, not other Bitaxe models/revisions.

To replace AxeOS, save its configuration first, then flash **`bitaxe-gamma-601-factory.bin` at `0x0` over USB**, or choose **Bitaxe Gamma 601 (experimental)** in the [web flasher](https://bdlglua.github.io/BDLMinerV1/). Factory flashing erases settings/statistics. See the [Gamma installation and validation guide](https://github.com/bdlglua/BDLMinerV1/blob/v1.6.1/docs/hardware/bitaxe-gamma-601.md).

Existing BDLMiner devices can install their matching signed **`*-firmware.bin`** through the local firmware-update page or GitHub update discovery. Gamma continues to default to checking/offering GitHub updates. The release includes signed firmware, factory images, signatures and SHA-256 checksums for all **eleven variants**.

Gamma defaults remain `public-pool.io:3333`, Stratum V1, suggested difficulty 1024 and automatic native identity **BDLMinerV1/1.6.1**. The pool must negotiate at least eight version-rolling bits and assign difficulty >=16. Public Pool's V1 endpoint does not accept V2; V2 requires a compatible server and authority key.

Existing ESP32 SHA-256d kernels, assembly paths and partition layouts are retained. **Reload the local dashboard after updating.**

## Validation and attribution

Validation covers **64 browser regressions**, **15 release/asset-tool tests**, native mining/protocol/persistence/OTA/thermal checks, encrypted Stratum V2 proofs, and eleven board builds. Simulated Gamma tests cover the 600 MHz ramp, error-rate fallback, missing/stalled counters, missing error telemetry, reconnect persistence, failed power-off and hard faults. Profile validation and persistence are tested for Gamma and existing boards.

Cold boot, real fan/temperature behavior, sustained counter-derived hashrate, accepted shares, power delivery and OTA/USB recovery still require validation on a physical Gamma 601. No measured overclock gain is claimed.

Gamma hardware/protocol references derive from [bitaxeorg/ESP-Miner / AxeOS](https://github.com/bitaxeorg/ESP-Miner/tree/bb4fd0c7e589858bbeef00ec89342216c1510671), revision `bb4fd0c7e589858bbeef00ec89342216c1510671` (GPL-3.0), and [bitaxeGamma hardware](https://github.com/bitaxeorg/bitaxeGamma). This is not an official Bitaxe/AxeOS release.
