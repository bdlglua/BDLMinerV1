## The WiFi setup portal after a failed attempt

Since 1.9.7 the setup portal runs from BDLMiner's own loop, which pauses between two
passes (the Bitaxe Gamma restarted twice on the task watchdog in the library's loop).
That library loop also did one more thing, lost in the change: after a failed connection
(a mistyped password, a network out of reach), it turned the miner's WiFi client off so
that its access point stays steady. Without it, the miner kept trying the wrong network
in the background, and the phone could drop off the portal while the typo was being
fixed. BDLMiner now notices each connection attempt and, when it fails, turns the client
off the same way; the next attempt turns it back on.

The rest of the portal was reviewed as well: it closes after 3 minutes without a phone
connected (never while one is), and the settings it shows are kept only once the WiFi
connection succeeds, so a mistyped password loses nothing.

Nothing else changes since [1.9.10](v1.9.10.md).

## Installation and compatibility

Existing BDLMiner devices install their matching signed **`*-firmware.bin`** through
GitHub update discovery (as a firmware trial) or the local firmware-update page;
settings, statistics and the hashrate history are kept. For a first install, pick the
board in the [web flasher](https://bdlglua.github.io/BDLMinerV1/) or flash its
**`*-factory.bin`** at 0x0. Signed firmware, signatures, factory images, SHA-256
checksums and the web flasher are provided for all **twelve variants**. The default
native user agent is **BDLMinerV1/1.9.11**.
