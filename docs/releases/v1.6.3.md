## Reduce local dashboard load while mining

Opening the local dashboard could compete with mining on the M5StickC Plus2.
This release reduces recurring HTTP traffic, page-framing overhead and response
buffer allocations, and lets the HTTP worker share core 0 with its software miner.
**The exact hashrate improvement has not been measured on a physical board.**

- Refresh dashboard statistics every **10 seconds instead of 3**: about 70% fewer
  recurring statistics requests when responses are fast. The first reading remains
  immediate. Hidden tabs still suspend polling, and slow requests do not overlap.
- Deliver each HTML page with an exact **Content-Length and four payload writes**,
  replacing many small HTTP chunks. Keep page bodies in flash and assemble only
  the small dynamic head in RAM. Set the initial HTML language correctly for
  English and French.
- Reserve the statistics response buffer before JSON serialization to avoid
  repeated String-buffer growth.
- Run the HTTP worker at **priority 1 on core 0**, sharing priority with the
  software miner instead of preempting it throughout each response. Hardware
  mining remains at priority 19 on core 1 on dual-core ESP32 boards; networking
  and thermal supervision retain their higher priorities.

SHA-256d kernels, assembly timing, nonce accounting, CPU frequency, temperature
limits and the safety lease are retained. A short initial Wi-Fi transfer can still
consume resources; no fixed 1 MH/s or zero-impact guarantee is made. See the
[dashboard-load review](https://github.com/bdlglua/BDLMinerV1/blob/v1.6.3/docs/audits/2026-10-27-m5-dashboard-load.md)
for scope and validation.

## Installation and compatibility

**Reload the local dashboard after updating** so it uses the new polling cadence.
Existing BDLMiner devices can install the matching signed **`*-firmware.bin`**
through GitHub update discovery or the local firmware-update page. For M5StickC
Plus2, use **`m5stickc-plus2-firmware.bin`**. Settings and saved statistics are kept
by an application update. Factory images are for USB installation and erase settings.

Signed firmware, signatures, factory images, SHA-256 checksums and the
[web flasher](https://bdlglua.github.io/BDLMinerV1/) are provided for all **eleven
variants**. The default native user agent is **BDLMinerV1/1.6.3**.

Gamma 601 retains **525–800 MHz profiles in 25 MHz steps**, **600 MHz / 1150 mV**
by default, automatic 525 MHz fallback and hard safety limits. Gamma support and
800 MHz operation remain experimental and unvalidated on a physical board.

## Validation

- **66 browser regressions**, including an unaccelerated-clock test of the
  ten-second statistics cadence, one immediate reading and no repeated history
  download.
- Production HTTP page-delivery tests for all three pages in English and French:
  exact byte length, four payload writes, intact HTML, language and versioned assets.
- **15 release/asset-tool tests**, native mining/protocol/persistence/upload/OTA/
  thermal checks, independent encrypted Stratum V2 proofs and eleven board builds.
- A separate diagnostic exercised the production M5 miner counters for two
  simulated hours at 1 MH/s across hardware/software/fill counters, including
  32-bit rollover, exact totals and rate decay after slowdown/stopping. This tests
  accounting logic, not physical SHA throughput.

Compare real hardware over equal dashboard-closed/open measurement intervals with
the same cooling, power and pool settings. Pool-estimated hashrate also depends on
accepted shares and its averaging window; the reported 1 MH/s versus 800 kH/s gap
has not yet been reproduced on a connected M5StickC Plus2.
