# BDLMiner V2 2.3.0

## Private monitoring from anywhere

You can now follow your own miners from a phone outside your home network without
leaving a computer or Raspberry Pi running. Open
[My miners](https://bdlminer-stats.bdlminer-bot.workers.dev/remote), create and save
your access key, then add it on each miner in **Settings → Network → Private remote
monitoring**. Choose a name, enable monitoring and save/restart once.

- Disabled by default and independent of anonymous public statistics.
- First report after about a minute, then every five minutes over CA/hostname
  verified HTTPS, with no redirects or insecure fallback.
- Hashrate, temperature, accepted/rejected shares, uptime, best difficulty,
  effective power, coin, firmware and pool connection/group; seven-day history.
- Separate private spaces for each 256-bit key; up to 32 miners per space.
- The key is masked locally and held in browser memory only. No key in URLs,
  permanent browser storage or public statistics. Disconnect clears the view.
- Erasing your space permanently revokes its key and deletes its readings.
- Readings only: remote monitoring cannot change settings, restart, calibrate
  or install firmware. Existing local controls and signed OTA remain available.

No payout address, worker, raw MAC, local IP, Wi-Fi/web password or configured
private pool host is sent. The cloud hosting operator can access stored readings;
this is authenticated private storage. Existing public opt-outs stay unchanged.

[Setup, API, privacy and limits](../remote-access.md).

## Validation

Tests cover the production firmware reporter, private key masking/persistence,
staged settings and opt-in scheduling, verified TLS failure handling, account
isolation, revocation, seven-day expiration, body/device limits, the real Worker
and SQLite backend, browser logout races, safe text rendering, English/French
and mobile layout. Physical cloud-report measurements on the owner's boards
remain to be performed after pairing; hashing kernels and ASIC profiles are unchanged.
