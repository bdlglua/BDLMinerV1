## Require version rolling for Stratum V2 ASIC mining

**Development build for validation.** Fix the client negotiation that could leave
a Gamma connected to a V2 pool at zero hashrate with **Pool needs version rolling**.

- Request `REQUIRES_VERSION_ROLLING` in `SetupConnection` on Gamma 601 and
  NerdNOS. Software ESP32 targets keep accepting fixed-version jobs.
- Interpret request and success flags separately. Refuse incompatible fixed
  versions and jobs without rolling before they reach the ASIC; never invent
  permission to modify version bits.
- Count an incompatible later job as an unusable session so configured backup
  failover can proceed, rather than remaining connected with a stopped ASIC.
- Keep the selected transport and user agent. There is no implicit downgrade
  from V2 to V1, and CPU/ASIC clocks, SHA-256d and hardware protections are unchanged.
- Extend independent Noise/socket tests for Gamma and NerdNOS, including the
  actual request bytes, refusal paths, valid rolled proofs and later job changes.

The complete native suite and 24 host-tool tests pass. Gamma 601 and NerdNOS
firmware builds pass. The owner confirmed that the 1.9.14 Gamma resumed mining
after the explicit Public Pool V1 workaround.

Physical validation of this corrective build on the owner's Public Pool
connection remains pending. On 1.9.14, an explicit switch to a compatible V1
pool/port is a temporary workaround; Public Pool uses `public-pool.io:3333` for
V1 and `public-pool.io:23330` for V2.
