## Pool and share reliability

- Stratum V1 now waits for successful worker authorization before publishing mining work or polling the share queue. A job received between subscription and authorization is retained and starts once authorization succeeds; a refused worker never starts that work.
- Finish partial TCP writes instead of treating a short write as a failed session. Bound the total write time and terminate on a failed connection or write. Show the actual Automatic / Manual identity mode in the V1 log.
- Apply Stratum V2 target changes according to each job's lifetime: jobs received with an explicit `ntime_start` retain their assigned target, while future jobs follow channel target changes, including after activation. Recheck queued shares against their own job's exact 256-bit target and report the active job's difficulty on the dashboard and device.

## Configuration and dashboard data

- Validate the effective protocol and authority key when a `stratum2+tcp://host:port/key` URL is pasted into either pool field. A URL cannot silently enable V2 with a missing or invalid authority key. Embedded keys and separately entered keys use the same whitespace normalization as stored settings.
- Keep pool API statistics associated with the endpoint that produced them. Hide obsolete main-pool readings after switching to the backup pool, and request fresh readings after failover instead of waiting for the previous refresh interval. Delayed responses from the previous endpoint cannot appear as results from the new pool.
- Handle TLS semaphore allocation or acquisition failure without dereferencing a missing lock, starting an unguarded handshake or disturbing the mining/watchdog locks. Reject overflowing TLS allocation sizes before allocating memory.

## Validation and performance

The audit covered the mining/work pipeline, V1/V2 sessions and crypto integration, settings and persistence, OTA ownership and signed GitHub updates, thermal supervision, display rendering, dashboard/history, pool API data and background services.

Regressions exercise the production code for early V1 jobs, short TCP writes, per-job V2 targets, V2 URL/key validation, pool-statistics failover and TLS allocation/lock failures. Validation also includes the existing SHA-256d vectors and filters, independent Noise responder and local fragmented-socket mining sessions, malformed-frame sanitizers, queue/persistence/OTA/thermal tests, physical-display rendering, release-tool checks, 49 browser regressions, and builds/USB packaging for all ten board variants.

The optimized hashing kernels, power settings, thermal throttling, expiring safety supervision and existing OTA partition layouts are retained. This release makes no new measured hashrate or temperature claims. Live Public Pool V2 connectivity, sustained hardware throughput and real board temperatures still require validation on physical devices.

## Updating

Install the firmware for your existing board variant. Signed firmware and the GitHub discovery manifest are included for all ten variants. Supported OTA updates preserve settings and statistics; boards without an OTA slot require USB. A first installation with a factory image erases the board.

After updating, reload the local dashboard. Existing protocol and user-agent selections are preserved.
