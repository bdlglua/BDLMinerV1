## Experimental native Bitaxe Gamma 601 firmware

BDLMiner can now be built and installed **in place of AxeOS on the Bitaxe Gamma revision 601**. This is experimental hardware support: **no physical Gamma 601 was available for validation**, and this release makes no measured ASIC hashrate, temperature or live-share acceptance claim.

- Add the dedicated `bitaxe-gamma-601` target for ESP32-S3 N16R8, one BM1370 and the 128×32 SSD1306 OLED. Other Bitaxe models and Gamma revisions are not covered by this target.
- Drive the BM1370 through its native UART protocol, with CRC validation, fragmented-response recovery, bounded work slots, duplicate screening and independent SHA-256d verification of returned nonces.
- Control the TPS546 regulator with verified volatile PMBus configuration and the EMC2101 ASIC temperature sensor/fan tachometer. Regulator NVM/STORE commands are never sent.
- Keep the ASIC reset and unpowered during provisioning. Pause it on lost jobs, OTA activity or expired supervision, and invalidate stale work on a clean job.
- Add independent interlocks for ASIC/regulator temperature, missing sensors, fan RPM, supply/core voltage, current and regulator faults. Assert reset before the I2C power-off command; hardware faults require a restart. Normal thermal pauses continue sampling so cooldown can be observed.
- Start at stock maximum **525 MHz / 1150 mV** with the fan at **100%**. Power limits from 10–100% reduce PLL frequency; 0 pauses. Values 1–9 keep the ASIC off with an explanatory status. No overclock controls are exposed.
- Show compact OLED pages for mining, power/thermal readings and pool/records. Add an **ASIC · BM1370** dashboard card with state, fan RPM, frequency, input/core voltage, current and regulator temperature. ASIC faults remain visible even when the pool connection is online.

## Version rolling and ASIC-scale statistics

- Negotiate BIP310 version rolling in Gamma Stratum V1 sessions and submit the negotiated version bits. Validate masks and discard obsolete work when the mask changes.
- Respect Stratum V2 extended-job version-rolling permission and reject changes outside the permitted BIP320 bits. Use an ASIC-scale channel-opening hint on Gamma; it is not presented as measured hashrate.
- Use the BM1370 hardware hash counter and 64-bit rate accounting on Gamma. The first response establishes the baseline; missing replies or a stalled counter stop mining.
- Preserve TH/s values in dashboard history instead of truncating them to a 32-bit integer, and display TH/s chart axes correctly.
- Count local difficulty records from ASIC-returned candidates (minimum difficulty 16); pool shares still use the assigned target.

## Installation and pool requirements

**Use a regulated 5 V barrel supply rated for at least 4 A, a fitted heatsink and a working 4-pin fan. USB alone cannot power ASIC mining.** Save your AxeOS settings before replacing its firmware.

The Gamma defaults are `public-pool.io:3333`, **Stratum V1**, suggested difficulty **1024**, and automatic native identity **BDLMinerV1/1.6.0**. A pool must negotiate at least eight version-rolling bits and assign difficulty >=16; incompatible pools are reported and the ASIC stays off. ESP32 low-difficulty ports such as 21496 are unsuitable for the Gamma target. Do not select V2 for Public Pool's V1 endpoint; V2 needs a separate compatible server and authority key.

For a first installation/replacing AxeOS, flash **`bitaxe-gamma-601-factory.bin` at `0x0` over USB**, or choose **Bitaxe Gamma 601 (experimental)** in the [web flasher](https://bdlglua.github.io/BDLMinerV1/). Factory installation erases settings/statistics. Follow the [Gamma 601 guide](https://github.com/bdlglua/BDLMinerV1/blob/v1.6.0/docs/hardware/bitaxe-gamma-601.md) for setup, limitations, validation and returning to AxeOS by USB.

Existing BDLMiner devices should use the signed `*-firmware.bin` matching their board for OTA. GitHub update discovery, signatures, SHA-256 checksums and factory images are provided for all **eleven variants**. Gamma defaults to checking/offering GitHub updates rather than installing them automatically.

Existing ESP32 software/hardware SHA-256d kernels, assembly paths and partition layouts are retained. Reload the local dashboard after updating.

## Validation and attribution

Validation covers **62 browser regressions**, **15 release/asset-tool tests**, native mining/protocol/persistence/OTA/thermal checks, independent encrypted Stratum V2 proofs, BIP310/V2 masks, simulated production Gamma I2C/UART startup and faults, ASIC candidate verification and 64-bit TH/s accounting, physical renderer checks and builds/USB packaging for eleven variants.

Real-board cold boot, power/fan behavior, sustained hash-counter accuracy, accepted pool shares, thermal control and OTA/USB recovery remain to be validated on a Gamma 601.

The Gamma board configuration, BM1370 register/packet conventions and TPS546/EMC2101 references derive from [bitaxeorg/ESP-Miner / AxeOS](https://github.com/bitaxeorg/ESP-Miner/tree/bb4fd0c7e589858bbeef00ec89342216c1510671) (GPL-3.0), revision `bb4fd0c7e589858bbeef00ec89342216c1510671`, and [bitaxeGamma hardware](https://github.com/bitaxeorg/bitaxeGamma). This is not an official Bitaxe/AxeOS release.
