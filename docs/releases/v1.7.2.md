## Home Assistant: no more temperature template warnings

The MQTT state payload left out the `temperature` key when there was no valid reading
(no sensor, a sensor fault, or before the first sample), and Home Assistant logged
`'dict object' has no attribute 'temperature'` for `{{ value_json.temperature }}`
([#2](https://github.com/bdlglua/BDLMinerV1/issues/2)).

- The key is now always present: `null` without a reading.
- The discovery templates use `{{ value_json.<key> | default(none) }}`, so a missing
  or null value shows as *unknown* instead of a warning. Home Assistant receives the
  new templates when the miner reconnects to the broker after the update.

Everything else is unchanged from [1.7.1](v1.7.1.md).

## Installation and compatibility

Existing BDLMiner devices install the matching signed **`*-firmware.bin`** through
GitHub update discovery (as a firmware trial) or the local firmware-update page. For
M5StickC Plus2, use **`m5stickc-plus2-firmware.bin`**. Settings, statistics and the
hashrate history are kept. Signed firmware, signatures, factory images, SHA-256
checksums and the web flasher are provided for all **eleven variants**. The default
native user agent is **BDLMinerV1/1.7.2**.

## Validation

- Native host tests and eleven board builds; the new template rendered with Jinja2:
  a missing or null value gives `None` (unknown in Home Assistant), a reading gives
  its value.
