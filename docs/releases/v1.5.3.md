## Local dashboard fixes

- Keep **Check now** usable after repeated checks, including when the next statistics response is unchanged.
- Immediately lock check/install controls while a command is pending, prevent simultaneous commands, and respect disabled update mode for both actions.
- Keep failed command messages visible instead of hiding them behind an older release-metadata error.
- Refresh live statistics independently of history and other miners. Slow or unreachable auxiliary endpoints no longer delay local readings; each scheduler still prevents overlapping requests.
- Keep valid charts and the pool's online status when inline history is malformed. Report history errors separately and discard delayed history responses from an earlier device boot.
- Require fresh statistics before starting a performance measurement. Record missing observations when a running measurement loses its statistics connection.
- Freeze the journal immediately when paused, including responses and errors already in flight.

## Pool statistics and release tooling

- Reject negative/non-finite ckpool hashrates, numeric overflow and trailing garbage. Preserve the previous valid rate when a field is missing or malformed; retain genuine zero rates and accept lowercase SI suffixes.
- Prepare firmware builds, signatures, checksums and manifests in staging before replacing release output. A failed later board or signature keeps the previous complete output; successful partial rebuilds retain other boards.
- Verify temporary signatures before publishing them. Fail if an explicitly configured signing-key file is missing, and validate CLI board names/version arguments before changing configuration.
- Generate complete installer sites in staging, reject missing declared factory images/unsupported chips/empty board lists, remove obsolete board files on success, and protect source directories from accidental replacement.
- Replace generated web headers and usage snapshots atomically. Recover from malformed usage caches and avoid negative or inflated activity estimates from new/decreased download counters.
- Require browser regressions to pass before the release workflow can publish firmware.

## Validation and compatibility

Validation includes **60 browser regressions**, **15 asset/release-tool tests**, native mining/protocol/persistence/OTA/thermal checks, independent encrypted Stratum V2 proofs and malformed-frame tests, physical renderer checks across seven panel sizes in English/French, and builds/USB packaging for all ten board variants.

The native user agent is **BDLMinerV1/1.5.3**. Explicit Manual identities and V1/V2 settings are preserved. Optimized SHA-256d kernels, assembly loops, thermal thresholds, safety supervision and partition layouts are unchanged. This release makes no new measured hashrate or temperature claim; sustained performance, temperatures and live pool operation still require physical-board testing.

## Updating

Install the signed firmware matching your board. Supported OTA updates preserve settings and statistics; boards without a second app slot require USB. Factory images are for a fresh installation and erase the board. Firmware signatures, SHA-256 checksums and the GitHub discovery manifest are provided for all ten variants.

Reload the local dashboard after the miner restarts so it loads the corrected scripts with their new cache version.
