# BDLMiner 2.0.0

V2 brings a fleet dashboard, pool diagnostics, assisted Gamma calibration and
configurable screens, while preserving existing settings and signed updates.
Stable remains the default update channel.

## What's new

- Optional Linux/Raspberry Pi fleet hub: live status, local history, controls,
  offline states and English/French UI. It runs separately from the miners.
- Pool diagnostics for Stratum V1/V2: connection, available work, ASIC version
  rolling, assigned difficulty and expected time between shares.
- Supervised Gamma frequency calibration using measured counter deltas, health
  checks, cancellation, restored settings and recovery after an interrupted run.
- Clearer local, pool and share-based rates; sample counts and rejected-share
  reasons. The local dashboard uses full-width sections and SVG settings icons.
- Configurable physical screen metrics, order and enabled pages, preserving
  fault/block/update priority and Gamma's native 128×32 display layout.
- Signed stable/beta channels with semantic version ordering and existing OTA
  trial/rollback. Stable 2.0.0 supersedes earlier V2 betas on either channel.
- Linux hardware checks, HTTP timing traces and OTA/network observers. All twelve
  board profiles build in parallel; a separate job verifies and signs the images.
- Specialized portable SHA-256d second hashing and removal of duplicate NerdNOS
  proof verification. S2/S3/C3 transfer kernels are self-tested and compared at
  boot, with buffered/full-write fallbacks. No physical speed gain is promised.

See the [V2 guide](../v2/README.md) for the hub, calibration and test commands.
The release includes `BDLMiner-2.0.0-Linux-kit.zip` with the hub, host tools and
verified M5/Gamma images. Extract it, edit `bdlhub.local.json` for your network
and run `sh start-hub.sh`; no board is flashed by launching the hub.

## Updating from V1 or a V2 beta

Use automatic signed updates, or upload only your exact board's
`<board>-firmware.bin` through its existing local settings page. Existing settings
and lifetime statistics retain their storage layout; new options have defaults.
The pool identity and setup access point keep the `BDLMinerV1` name for
compatibility. Updating the firmware does not change the selected pool protocol.

The [web installer](https://bdlglua.github.io/BDLMinerV1/) is for USB installation.
Its factory image and erase prompt can remove settings/statistics: keep a backup
before using that route. `*-factory.bin` is not a local-dashboard OTA image.
V1.9.15 remains available in the release archive.

## Validation and known limits

The owner tested the matching beta.4 code on M5StickC Plus2 and Gamma 601: both
OTA trial/confirmation sequences, M5 physical rollback and same-boot network
recovery, short counter checks, and a clean Gamma hour. That hour measured
**1.070391 TH/s over 3,604 seconds**, +119 accepted shares and no new rejection,
with 715 error-free HTTP reads. Its declared conditions were dashboard closed
and hub stopped. The stable build changes the version label; these are explicitly
candidate-version observations, not a newly measured 2.0.0 run.

S2/S3/C3 and NerdNOS physical V2 measurements remain unavailable. Their profiles
build and have automated coverage; external-project benchmarks and anonymous
usage reports do not replace controlled BDLMiner measurements. **1 MH/s is not
promised for every ESP32 family.** Gamma and NerdNOS retain experimental hardware
status and their existing electrical, cooling and thermal requirements. Longer
duration/load tests and full physical-screen acceptance are not established for
every board. See the [hardware record](../v2/hardware-validation.md) and
[external board research](../audits/2026-11-02-board-hashrate-research.md).
