## Safer updates, crash reports and alerts

**Firmware trial and automatic rollback.** A newly installed firmware, from GitHub or
the web page, now starts on trial. It is kept once it has run 3 minutes connected to
the pool and hashing. If it crashes or hangs first, or does not get there within
20 minutes (40 without WiFi), the previous firmware comes back by itself and a
notification is sent. A version gets a second try (a power cut during the trial also
rolls back); rolled back twice, it is no longer installed automatically.

**Crash reports.** After a crash, the log and a *Last crash* tile on the dashboard show
a summary (task, address, cause, backtrace). **Download report** saves the full core
dump for `esp-coredump` / GDB, and **Erase** clears it.

**Alerts and webhook.** *Hashrate low* when the hashrate stays under 50 % of its usual
full-power level for 15 minutes (both adjustable, 0 = off), then *Hashrate back to
normal*; *Shares rejected* when at least 5 shares and 10 % are refused over that span.
Every notification can also go to a webhook as JSON, read directly by Discord and
Telegram, with ntfy or without it. **Send a test notification** in the settings shows
whether each destination accepted it.

**Home Assistant control.** Besides the sensors, MQTT discovery now adds a *Mining*
switch, *Power* and *Brightness* numbers and a *Restart* button.

**Touch screens.** On CYD and M5Stack Core2 / CoreS3, a tap shows the next screen and a
one-second press changes the brightness.

**Block found.** A full-screen *BLOCK FOUND!* alert with the block height stays until a
button is pressed, even in night mode.

**New settings and log pages.** Settings are grouped in cards with a side
navigation, short titles with a hint, and real choices instead of codes (language,
rotation, colour theme, night-mode hours, GitHub updates, currency), switches and
units. Changed fields are marked, and a floating bar saves them or discards them.
The activity log shows a summary (entries, warnings, time covered, last start),
filters by category or warnings, coloured tags, highlighted problems and search
matches, and follows new lines.

**Pool statistics found automatically.** Instead of two pools known by name, the
miner finds the statistics API of any pool (ckpool and public-pool formats, on the
pool's host, its parent domain and the usual ports), remembers it, and shows where the
figures come from. The Public Pool preset buttons are gone from the settings: pasting
a `stratum2+tcp://` address still fills the protocol, port and key.

**Home-screen dashboard.** The dashboard has a web app manifest and icon: added to a
phone's home screen, it opens full screen like an app.

## Installation and compatibility

Existing BDLMiner devices install the matching signed **`*-firmware.bin`** through
GitHub update discovery or the local firmware-update page. For M5StickC Plus2, use
**`m5stickc-plus2-firmware.bin`**. Settings and saved statistics are kept. 1.6.8 itself
already starts on trial and is confirmed as soon as it mines; remembering a failed
version so that it is not installed again works from the next update on, since 1.6.8
is the one installing it.

Signed firmware, signatures, factory images, SHA-256 checksums and the web flasher are
provided for all **eleven variants**. The default native user agent is
**BDLMinerV1/1.6.8**.

## Validation

- 68 browser regressions, native host tests, display previews of the new alert on
  seven screen sizes and eleven board builds.
- On an M5StickC Plus2: a test firmware that crashes 20 s after boot was rolled back
  by itself, with its crash report kept; crashing a second time, it was refused. A
  good test firmware was confirmed after 3 minutes of mining and stayed after a
  restart. The manifest, icons and crash summary are served by the device. A test
  notification reached a Discord channel through the webhook.
