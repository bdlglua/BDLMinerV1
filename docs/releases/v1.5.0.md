## Stratum V2 and pool connection choices

- Add native Stratum V2 alongside Stratum V1. Select the protocol independently for the main and backup pool in the local dashboard or setup portal. Existing installations retain V1 by default.
- Establish encrypted Noise_NX connections using secp256k1 EllSwift, BIP340 authority signatures and ChaCha20-Poly1305. Require a pool authority key and synchronized time; reject invalid signatures, expired certificates, unauthenticated messages and replayed records. The selected endpoint never silently downgrades to V1.
- Support extended mining channels, future/current jobs, previous-block changes, exact 256-bit share targets and batched share acknowledgments. Retain unique extranonces across workers and recheck targets before submission. Duplicate and unknown acknowledgments do not increase share counters.
- Add Public Pool solo presets: V1 on `public-pool.io:3333`, or V2 on `public-pool.io:23330` with its published authority key. Each preset preserves the configured payout address. Public Pool's separate PPLNS endpoint is not selected by these presets.

## Automatic or manual user agent

- Choose **Automatic** or **Manual** in the dashboard or setup portal. Automatic selects a compatible identity for known ESP32 pools and can retry an explicitly refused identity once. Main and backup pools retain separate decisions.
- Manual uses the configured custom identity without automatic replacement. Keep that value when switching back to Automatic. Migrate older customized identities to Manual and older default identities to Automatic.
- Display the effective identity, identity mode and selected protocol in the dashboard's Pool card. Keep protocol, authority keys and identity settings in backups and persistent settings.

## Memory, performance and validation

Keep the existing SHA-256d hashing kernels, mining power controls, thermal protection and illustrated physical display. Bound V2 frames to 16 KiB, cache up to eight jobs with 32 KiB of coinbase data, and reconnect with diagnostics for unsupported or oversized jobs. Use pinned libsecp256k1 and Monocypher sources with their upstream licenses; the compact crypto implementation keeps the LilyGO T-Display within its existing OTA application slot.

Validation includes an independent Noise responder, official authority-key vectors, certificate/AEAD/replay failure cases, malformed and truncated frame checks under sanitizers, independent coinbase/Merkle/header verification, and the production network session over fragmented local sockets with partial writes. Core, persistence, display and release-tool regressions are retained, alongside 49 browser regressions and builds/USB packaging for all ten board variants.

Live Public Pool connectivity and physical-device V2 throughput have not been validated on hardware. Protocol choice does not override the pool's share difficulty or increase the device's hashing power; this release makes no new measured hashrate or temperature claims. Job Declaration, Template Distribution and operating a V2 pool server are outside this implementation.

## Updating and connecting

Choose the firmware for the same board as your existing installation. Supported OTA updates preserve settings and statistics. Boards without OTA support use USB; a first installation with the web flasher erases the board. Signed firmware and the GitHub update manifest are included for all ten variants.

After updating, reload the local dashboard. Under Pool, choose the main/backup protocol and user-agent mode, or apply a Public Pool solo preset, then save and restart. Public Pool uses your Bitcoin address (optionally `.worker`) as the worker identity. V2 requires the V2 port and authority key; check the pool's [published connection details](https://web.public-pool.io/) if they change. The V1 password setting is not sent as a V2 authentication field.
