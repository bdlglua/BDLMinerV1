## Native BDLMiner identity

- Use `BDLMinerV1/1.5.2` by default on every pool, including ESP32/NerdMiner endpoints. The manual field also defaults to the native identity.
- Retry as `NerdMinerV2` only after an explicit user-agent refusal in Automatic mode. Keep main and backup compatibility decisions separate. Manual mode preserves the configured identity without automatic replacement.
- Migrate the old `NerdMinerV2` default in Automatic settings to the native identity; preserve explicit Manual choices and other saved custom identities.

## Pool and share reliability

- Require a boolean Stratum V1 authorization result, reject empty job IDs and ignore duplicate successful authorization replies. Display the difficulty of the active job rather than an announcement for the next job.
- Handle Stratum V2 extranonce-prefix updates and group reassignment without reconnecting. Preserve the prefix belonging to each received job, including future jobs activated later. Ignore group-addressed prefix changes and unrelated channel closures; validate truncated messages before mutating state.
- Accept pool API difficulty/share/hashrate values as JSON numbers or numeric strings. Preserve previous valid difficulty/share records when a value is missing, negative, non-finite or malformed. Match Public Pool hostnames at a DNS-label boundary.

## Settings, dashboard and update safety

- Parse complete `stratum2+tcp://host:port/authority` URLs into the correct host, port, protocol and key fields. Keep main and backup controls independent.
- Reveal invalid settings hidden by the settings search before browser validation, so Save identifies a visible field to correct. Retain numeric, power and temperature checks.
- Reserve update ownership before automatic restarts and physical factory resets. Defer web restarts during GitHub OTA; allow a completed web update to reboot while retaining its ownership. Prevent a new update from starting during a reserved restart.
- Keep scheduled web restarts working when the millisecond counter wraps after approximately 49.7 days.
- Bound the settings payload again before size arithmetic and copying. Preserve the existing dual-slot/CRC storage format, verify the 8,192-byte boundary and oversized rejection, and remove the native compiler's oversized-copy warning.

## Validation and performance

Validation covers the portable SHA-256d kernels and filters, mining queues and 32/64-bit records, settings/statistics persistence, OTA/restart fault cases, thermal supervision, signed-update discovery, independent Noise/AEAD/certificate checks, malformed-frame sanitizers, four independently reconstructed mining proofs across V2 prefix/group changes, fragmented local TCP sessions, 51 browser regressions, physical rendering in English/French on seven panel sizes, release tooling and builds/USB packaging for all ten board variants.

The optimized SHA kernels, assembly loops, thermal thresholds, saved user limits, safety lease and partition layouts are retained. No new measured hashrate or temperature claim is made. Actual board temperatures, sustained performance, hardware flash/reboot behavior and live Public Pool V2 operation still require physical-device testing. See the [audit report](https://github.com/bdlglua/BDLMinerV1/blob/v1.5.2/docs/audits/2026-10-27.md).

## Updating

Install the firmware matching your current board. Supported OTA updates preserve settings and statistics; boards without an OTA slot require USB. Factory images are for first installation and erase the board. Signed firmware, checksums and the GitHub update manifest are included for all ten variants.

Reload the local dashboard after updating. Existing protocol and explicit Manual identity selections are preserved.
