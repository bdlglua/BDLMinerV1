# BDLMiner V2 2.5.0

The firmware moves to **Arduino-ESP32 3.3.12** (ESP-IDF 5.5, GCC 14.2, **C++23**).
Settings, statistics, pool profiles, mining kernels, screens and web pages are
unchanged from [2.4.2](v2.4.2.md); the partition tables are the same, so the update
installs over WiFi like any other and keeps everything.

- **TLS 1.3: the miner reads public-pool's statistics itself again.** public-pool.io
  serves its statistics API (port 40557) over TLS 1.3 only, which 2.4.2's TLS (1.2)
  could not use: *Seen by the pool* came from the dashboard's own request, while it
  was open, and the miner's screen kept an estimate. The firmware now speaks TLS 1.2
  and 1.3. The dashboard's request from the browser stays as a fallback for any pool
  whose API the miner cannot read.
- **New platform, same size.** ESP-IDF is rebuilt for the project and leaves out what
  the firmware does not use (Bluetooth, Ethernet, IPv6, WPA-Enterprise, C++
  exceptions, the TLS server side, unused ciphers and curves). The 4 MB boards keep
  their two 1920 KB update slots, with more room than before: T-Display 1733 KB (90 %,
  was 92 %), CYD 1733 KB (90 %), M5Stack ESP32 1847 KB (96 %, was 98 %).
- **Certificates.** The 40 root certificates the firmware already trusts become
  ESP-IDF's certificate bundle too, in the format ESP-IDF 5.4+ expects.
- **Building from source** needs PlatformIO Core 6.2.0; the first build of each board
  rebuilds ESP-IDF and takes several minutes. See
  [development.md](../development.md#build-and-flash).
- WPA2/WPA3 personal networks are unchanged; WPA2-Enterprise (802.1X) networks, never
  offered by the setup portal, are no longer supported. ESP32-C6/H2 are still not
  built.

## Validation

All host, tool and browser tests and every board build pass. On a Bitaxe Gamma 601,
updated from 2.4.2 through its web page: shares accepted and none rejected, about
1.09 TH/s at 525 MHz / 1150 mV as on 2.4.2; market data read over TLS 1.3 from
mempool.space (handshake about 1 s), public-pool's statistics read by the miner, and
a further update installed from the web page. Testing it found four differences of
the new platform, fixed before this release: the SHA engine's lock is no longer
re-entrant (HTTPS and update checks waited forever on the S2, S3 and C3), TLS 1.3 needs
its crypto set up first, a response body was cut at the first gap between TLS records,
and timeouts are now in milliseconds. The other boards were built and packaged but not
run on hardware.
