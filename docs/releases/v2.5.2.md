# BDLMiner V2 2.5.2

Hashrate fix for the ESP32-S2, S3 and C3 boards; settings, screens and web pages are
unchanged from [2.5.1](v2.5.1.md) and the update installs over WiFi.

- **The S2, S3 and C3 mine with their SHA engine again.** Since 2.5.0 the engine was
  left computing SHA-1: ESP-IDF 5 resets it each time it is taken and no longer selects
  the algorithm when a block starts. The boot self-test then failed and these boards
  mined in software only, about four times slower (an ESP32-S3 at 66 instead of
  288 kH/s). The engine is now set to SHA-256 every time. Classic ESP32 boards
  (M5StickC Plus2, T-Display, CYD, M5Stack ESP32) and the ASIC boards were not affected.

## Validation

All host, tool and browser tests and every board build pass. The S2/S3/C3 engine model
of the host tests now resets the algorithm when the engine is taken, as ESP-IDF 5 does:
2.5.1's code fails it, 2.5.2's passes. Not yet run on an S2, S3 or C3 board. 2.5.1 was
checked on an M5StickC Plus2 (PSRAM back, updates from GitHub again, about 960 kH/s).
