## Gamma 601 profiles up to 800 MHz

The Bitaxe Gamma revision 601 can now select **525–800 MHz in 25 MHz steps** under local **Settings > Safety > Gamma ASIC frequency (MHz)**. The twelve profiles include the new **625 / 650 / 675 / 700 / 725 / 750 / 775 / 800 MHz** choices. Changes apply after restart and are included in settings backups.

**Gamma support remains experimental: no physical Gamma 601 was available for validation.** Selecting 800 MHz does not guarantee stable mining or a particular hashrate. Actual hashrate, temperature, stability and accepted pool shares still require hardware measurements.

- Keep the default at **600 MHz**, core voltage at **1150 mV**, and the fan at **100%**. Existing saved profiles are preserved; there is no automatic switch to 800 MHz.
- Extend BM1370 PLL generation and strict settings/API validation through 800 MHz. Reject frequencies above the limit, values between profiles, fractional values and strings masquerading as numbers. Invalid stored profiles still fall back to 525 MHz.
- Add all twelve profiles to the dashboard settings and explain the experimental range in English and French. Preserve a saved 800 MHz selection when reopening settings.
- Retain the automatic **525 MHz fallback until reboot** for sustained hardware errors, missing/stalled hash counters or unavailable hardware-error telemetry when running above stock. A failure at stock stops mining.
- Retain latched shutdowns for thermal, fan, sensor, supply, current and regulator faults. Voltage and hard safety limits are not raised to reach the requested frequency. Startup remains supervised throughout the PLL ramp.
- Keep hashrate based on the ASIC hardware counter and retain frequency/error/fallback diagnostics. Add a [three-page OLED preview](https://github.com/bdlglua/BDLMinerV1/blob/v1.6.2/docs/images/gamma601-oled-v1.6.1.png) with clearly marked fictional demo values.

## Installation and updates

Existing BDLMiner devices should install their matching signed **`*-firmware.bin`** through the local update page or GitHub update discovery. Gamma continues to default to checking/offering updates. Reload the local dashboard after updating, choose a profile, save and restart.

For a first installation replacing AxeOS, save its configuration and flash **`bitaxe-gamma-601-factory.bin` at `0x0` over USB**, or select **Bitaxe Gamma 601 (experimental)** in the [web flasher](https://bdlglua.github.io/BDLMinerV1/). Factory flashing erases settings/statistics. The Gamma image is only for revision **601**.

Use regulated **5 V barrel power**, a fitted heatsink and a working fan; USB alone cannot power ASIC mining. The [Gamma guide](https://github.com/bdlglua/BDLMinerV1/blob/v1.6.2/docs/hardware/bitaxe-gamma-601.md) covers power requirements, safety limits, pool requirements and restoring AxeOS. No supply/thermal validation at 800 MHz is claimed.

All **eleven variants** retain signed firmware, signatures, factory images and SHA-256 checksums. Existing ESP32 SHA-256d kernels, assembly paths and partition layouts are retained. The default native user agent is **BDLMinerV1/1.6.2**.

## Validation and attribution

Validation covers **65 browser regressions**, **15 release/asset-tool tests**, native mining/protocol/persistence/OTA/thermal checks, encrypted Stratum V2 proofs and eleven board builds. New checks decode PLL register fields throughout the startup range, exercise all twelve profiles, preserve 1150 mV/full fan at 800 MHz, verify error/watchdog fallback and hard shutdown at the highest profile, and test API validation and profile persistence. Browser checks cover numeric 800 MHz saves and reopening the saved profile in French.

The [regulator/startup fixes from v1.6.1](https://github.com/bdlglua/BDLMinerV1/blob/v1.6.2/docs/releases/v1.6.1.md) remain included. Cold boot, sustained counter-derived hashrate, accepted shares, cooling, power delivery and OTA/USB recovery still require a physical Gamma 601 test.
