## Reliability fixes

- Settings saves now require a successful write and CRC-checked readback. Failed saves return an error and do not schedule a restart.
- Store complete settings in alternating protected records; import existing preferences automatically. A failed or interrupted write keeps a valid previous record available.
- Verify statistics writes too. Failed saves retain their dirty state for retry, and a failed restore does not freeze future saves or report success. A partial backup restore explicitly reports when settings were saved but statistics were not.
- Count each share response once and only for a real outstanding submission. Ignore unsolicited, duplicate and invalid request IDs, bound pending submissions and reconnect if acknowledgments stop arriving.
- Retry interrupted GitHub installations after 5 minutes, then 10, 20 and at most 30 minutes. Show the countdown and allow immediate retry. Refused signatures and USB-only boards do not repeatedly attempt installation.
- Read the signature's declared byte length instead of waiting for the maximum signature buffer to fill.

## Useful performance tools

- Live polling uses a lightweight stats response. Download the history only when a new point is available instead of sending all points every three seconds.
- Add aligned temperature, effective-power and hashrate history, with missing-data handling, observation coverage and CSV export.
- Add elapsed worker-batch, rest, waiting and pause counters, plus TLS handshake counts, durations and failures. Counters are measured between batches and do not change the accelerated SHA loops.
- Add a ten-minute measurement based on actual hashes and device uptime, with an optional early finish and a downloadable JSON report. Include sampled temperatures/power and profiling differences.
- Use a per-boot identifier to invalidate stale charts and measurements. Cancel measurements across a restart or hidden tab, and flag significant observation gaps.

## Upgrade and measurement notes

Existing settings, mining power and thermal protections are preserved. This release does not overclock the chip or guarantee 1 MH/s. Profiling durations are elapsed worker time, not CPU utilization; TLS does not suspend the classic ESP32 hardware miner. Reported temperature extrema are sampled observations.

The settings storage format changes to protected snapshots. Export a JSON backup before downgrading, because older firmware reads the legacy preference keys. Backup files remain portable between supported firmware versions.

Validation covers storage open/write/readback failures, truncated/corrupt records and generation wrap, real settings HTTP handlers, statistics recovery, share-response tracking, retry scheduling, aligned history and browser measurements. Builds and factory-image packaging are checked for all 10 boards. Physical sustained-hashrate and temperature testing still requires a device.
