## Gamma fan control and mining reliability fixes

### Bitaxe Gamma 601

- Add **Manual 30–100%** and **Automatic** fan modes under local
  **Settings > Safety > Cooling**. Changes save and apply without restarting
  the ASIC; mode and manual preference are included in backups.
- Preserve **manual 100%** for existing devices. Startup, a stopped ASIC and
  unavailable temperatures request full cooling. At default settings, **60 °C
  ASIC / 80 °C regulator** forces full cooling until both cool by 5 °C. A lower
  configured thermal limit advances cooling. Disabling the user limit keeps
  cooling safety and the independent hard shutdowns active.
- Automatic cooling rises immediately and reduces gradually. PWM writes are
  verified; a controller error asserts ASIC reset before requesting regulator
  shutdown and full fan speed, then latches the fault.
- Display the verified fan command, measured RPM, mode and cooling override.
  An unverified command is shown as unknown. Controls and help support English
  and French, including mobile and keyboard use.

### NerdNOS

- Publish each verified ASIC result immediately; the dashboard no longer waits
  for a 50-result error-statistics window to update its counter.
- Interrupt ASIC startup when pool work disappears, holding reset and cutting
  power instead of finishing initialization on obsolete work.

### Pool, dashboard and notifications

- Require initial usable work within the 30-second Stratum V1/V2 setup deadline.
  Authorization without work counts as a failed session, allowing three failed
  main-pool attempts to select the configured backup. Existing valid work does
  not need a refresh every 30 seconds.
- Ignore a late poll's response or error after newer live data arrives. Old
  requests cannot restore a previous boot's readings or falsely mark it offline.
- Cancel measurement preparation if the miner restarts while diagnostics are
  in flight, including restarts with higher counters.
- Match notification tests to their request IDs and retain the last eight test
  results independently of ordinary alerts. A full queue returns a retryable
  error. Settings edits cannot unlock a pending test or discard its result.
- Retry failed bootloader confirmation while retaining the pending firmware
  trial and its metadata. Clear the trial only after confirmation succeeds.

### ESP32-C3 and compatibility

- Specify the supported **160 MHz** CPU clock for ESP32-C3 instead of inheriting
  the other boards' 240 MHz request. Reject C3 builds requesting more than
  160 MHz. This fixes a configuration mismatch, not a verified physical overclock.
- Retain the other CPU clocks, ASIC frequency profiles, regulator setpoints,
  SHA-256d kernels and hard thermal/fan/supply shutdown thresholds.
- Provide matching signed firmware, signatures, factory images, checksums and
  web-flasher manifests for all **12 variants**. The native user agent becomes
  **BDLMinerV1/1.9.13**; existing manual identity choices are preserved.

### Validation and installation

The full native suite covers SHA-256d, Stratum V1/V2 and independent Noise
cryptography, persistence, firmware trials and ASIC fault injection. This release
also passes **93 browser regressions**, **16 tool tests**, display-renderer checks
at seven sizes in English/French, and builds for all twelve variants.

Gamma 601 and NerdNOS support remains **experimental**. Fan starting behavior,
RPM and thermal response have not been measured on physical hardware; no actual
hashrate gain or overclock stability is claimed. The default full fan and the
existing hard shutdowns are retained.

For an existing installation, use the matching signed **`*-firmware.bin`** through
GitHub updates or the local firmware-update page, then reload the local page.
Settings, lifetime statistics and history are kept. For a first installation,
use the [web flasher](https://bdlglua.github.io/BDLMinerV1/) or the matching
**`*-factory.bin`** at **0x0**.
