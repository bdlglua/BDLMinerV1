## Library updates and a more useful log

- **ArduinoJson 7.4.3** (from 7.4.2) fixes a buffer overrun in `as<T>()` when a
  numeric value arrives as a very long decimal string. The firmware reads JSON
  from the pool, mempool.space, GitHub and the dashboard forms.
- **M5GFX 0.2.35** and **M5Unified 0.2.28** (from 0.2.31 / 0.2.24) fix I2C bus
  hangs and lock leaks, SPI transfer issues and M5Stack Core2/CoreS3 power-on
  problems on weak USB supplies.
- **The log keeps hours of events instead of about a minute.** Each share wrote two
  lines into its 6 KB buffer, so boot messages, TLS errors and disconnections were
  gone within roughly 80 seconds. Accepted shares and routine job updates are no
  longer logged one by one: the 30-second `[stats]` line counts them. Rejections,
  errors, shares of difficulty 1 and above, and each new block are still logged.
- **A saved `BDLMinerV1/<version>` user agent follows the firmware version.** In
  manual mode it kept announcing the version it was saved with; it now reports the
  running version. Other manual user agents are unchanged.
- **Dashboard:** the device card shows free memory in the same unit as the memory
  card, and chart axes use the same decimal point as the rest of the page.

Build and CI: GitHub Actions moved to their Node.js 24 majors (the "Node.js 20 is
deprecated" warnings are gone), web tests run on Node.js 24, and the display
preview builds with the split M5GFX sources.

Hashing code, assembly timing, thermal limits and the PlatformIO ESP32 platform
(6.9.0, Arduino core 2.0.17) are unchanged.

## Installation and compatibility

Existing BDLMiner devices install the matching signed **`*-firmware.bin`** through
GitHub update discovery or the local firmware-update page. For M5StickC Plus2, use
**`m5stickc-plus2-firmware.bin`**. Settings and saved statistics are kept by an
application update. Factory images are for USB installation and erase settings.

Signed firmware, signatures, factory images, SHA-256 checksums and the
[web flasher](https://bdlglua.github.io/BDLMinerV1/) are provided for all **eleven
variants**. The default native user agent is **BDLMinerV1/1.6.5**.

Gamma 601 support and profiles above 525 MHz remain experimental and unvalidated
on a physical board.

## Validation

- Native host tests, release-tool tests and display previews at all seven panel
  sizes in English and French; eleven board builds with firmware sizes within
  1 KB of 1.6.4.
- On an M5StickC Plus2 mining on eu.findmyblock.xyz: self-tests passed, about
  1004 kH/s with no rejected share, the user agent reported as `BDLMinerV1/1.6.5`,
  and the log showing only events and the periodic `[stats]` line.
